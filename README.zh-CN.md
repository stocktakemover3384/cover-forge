# CoverForge · 封面工坊

**把一张图，锻成各平台要的封面尺寸 —— 全程在浏览器本地完成。**

[English](README.md) · [使用说明（中文，详细）](USAGE.zh-CN.md) · [Usage guide](USAGE.md)

CoverForge 是一个单页、零依赖的封面处理工具，只做一件事：把一张照片或截图
变成某个平台能用的封面。它按你选的比例裁切（永远居中填满，绝不拉伸变形）、
缩放到平台像素、再压到指定的文件大小（比如 500 KB）——只依赖浏览器原生的
Canvas，不装任何东西、不联任何网。

平台对封面比例、体积和页面重量的限制都是硬指标。这个工具把它们当作第一等的
输入参数，而不是等你上传之后才发现超标。

**在线直接用：<https://zyphraxns.github.io/cover-forge/>** —— 或者克隆仓库后打开 `index.html`。
放在网上也完全一样：即便是网页版，图片处理依然只在你本机完成。

打开 `index.html`，安装就结束了。

## 功能

**上传 —— 三种方式**
- 点击上传区（或聚焦后按 `Enter`）
- 把文件拖到页面任意位置
- 用 `Ctrl`+`V` / `⌘`+`V` 粘贴（截图直接可用）

**原图信息**
- 文件名、像素尺寸、像素量（MP）、约分比例（`16:9 · 1.778`）、文件大小、格式、是否含透明通道
- 素材较大（≥ 800 万像素）时提示处理可能需要几秒

**画面比例**
- 10 个通用比例：16:9、9:16、1:1、3:4、4:3、4:5、5:4、2:3、3:2、21:9
- 7 个平台预设，带推荐像素（见下表）
- 自定义比例，支持小数（如 `2.35 : 1`），非法输入就地报错

**裁剪**
- 永远填满目标比例（cover）：不变形、不留黑边
- 默认居中；在预览里拖动可移动取景，或用九宫格焦点按钮
- 两种预览视图。**成片**显示的就是即将下载的那份像素；**原图取景**显示完整原图、
  叠加裁剪框并把框外压暗 —— 让你在裁之前就看见会裁掉什么
- 点左侧流程里的「05 取景」会直接切到原图取景视图
- 「重置居中」，三分线可开关（原图取景下三分线会跟随裁剪框，那才是它有意义的位置）
- 面板显示裁切区域与横 / 纵向余量（像素）

**目标文件大小**
- 不限（最高画质）、200 KB、500 KB、1 MB、2 MB，或自定义 KB / MB（上限 50 MB）
- 小于 50 KB 时提示画质损失会比较明显
- JPG：先二分搜索「能达标的最高的 JPEG 质量」；质量触底仍超标才分级降分辨率，
  两种结果都如实告知
- PNG：明确说明它是无损格式、体积不可控，并提供一键「改为 JPG」以达标

**输出尺寸**
- **最大可用**（默认）——不会主动降分辨率
- **平台推荐**——一键套用预设像素
- **自定义长边**——1920 / 1280 / 1080 / 800 快捷值，或 16–10000 之间任意值，等比缩放

**放大**
- 当要求的输出大于裁切区域时，逐级放大（每步最多 2×，高质量插值），并如实
  提示倍数：*「将放大 4.80×，多出的细节由插值生成」*

**导出**
- JPG（质量自动，或手动覆盖）与 PNG
- 透明原图导出 JPG 时，可自选填充的背景色（4 个快捷色板 + 取色器）
- 导出前信息面板：输出尺寸、比例、格式、目标体积、预估文件大小、编码质量、
  分辨率变化、处理耗时、目标达成判定
- 文件名规则 `<原名>-<比例>-<宽x高>.<扩展名>`，例如 `cover-16x9-1920x1080.jpg`
- 结果提示分成功 / 信息 / 警告 / 错误四类；如果刚下载的文件超出目标体积，会额外给一条
  明确的警告

**界面**
- 深色工作台主题：屏幕上最亮的只有你的图
- 桌面三栏工作区，窄屏自动收成单列
- 键盘可操作、焦点环可见、`aria-live` 提示、支持 `prefers-reduced-motion`

## 平台预设

| 预设 | 比例 | 推荐输出 |
|---|---|---|
| Bilibili 视频封面 | 16:9 | 1920 × 1080 |
| YouTube 缩略图 | 16:9 | 1280 × 720 |
| 抖音 / 快手 / 视频号 | 9:16 | 1080 × 1920 |
| 小红书封面 | 3:4 | 1080 × 1440 |
| Instagram 帖子 | 4:5 | 1080 × 1350 |
| 方图 / 头像 | 1:1 | 1080 × 1080 |
| 公众号头图 | 2.35:1 | 1175 × 500 |

点预设卡片本体 = 只套用比例；点卡片上的「套用」按钮 = 套用比例 **并** 把输出尺寸
切到推荐像素。选自定义比例时会自动退回「最大可用」，避免不小心导出成不匹配的尺寸。

## 快速开始

```bash
cd cover-forge
open index.html        # macOS
xdg-open index.html    # Linux
start index.html       # Windows
```

或者直接双击 `index.html`。

- **不需要安装**：没有包管理器、没有构建步骤、没有运行时依赖。
- **不联网**：一个本地样式表、一个本地脚本、一个 data URI 内联图标、系统字体栈，
  运行时不会发起任何请求。
- **`file://` 可用**：`app.js` 刻意写成经典 script + IIFE —— `file://` 下
  `<script type="module">` 会被 CORS 拦截，而 CoverForge 不该要求起服务器。
- 起本地静态服务器（`python3 -m http.server`）也能用，但没有必要。

### 隐私

图片不会离开这台设备。没有上传、没有埋点、没有分析、没有 Service Worker、没有
任何外部请求 —— 测试用例会断言「非 `file://` 请求数为 0」。所有像素处理都在浏览器
自己的 Canvas 里完成，关掉标签页不留任何痕迹。

## 实现要点

**一条画布管线。** 裁切区域先 1:1 拷进离屏画布，再重采样到输出尺寸，最后
用 `canvas.toBlob` 只编码一次。图片不会被反复重编码，画质只损失一次。

**渐进式重采样。** 放大时每步最多 2×，配合 `imageSmoothingQuality = 'high'`，
而不是一次性插值到位。这样避免了一次 5× 放大常见的锯齿与刻痕。

**二分搜索满足体积上限的最高质量。** 给定目标体积时，先在质量下限（`0.40`）
编码一次判断可行性，再在 `0.40`–`0.95` 之间二分 9 次，取仍然达标的最高质量。
质量始终顶到预算允许的上限。

**只有质量触底才降分辨率。** 如果连 `0.40` 都超标，就按 `√(目标 / 下限体积)`
估算所需面积，把步长夹在 0.35–0.9 之间降档重试（最多 6 轮）。少几个像素，
比糊成一片好看 —— 所以先牺牲质量、后牺牲分辨率。目标确实不可达时，返回当前
能达到的最小体积，并明确标注出来。

**预估值就是文件本身。** 面板里的「预估文件大小」正是下载按钮将要交给浏览器的
那个 blob 的字节数 —— 没有单独的估算环节；点击下载时会等当前状态渲染完成再触发。

**不会画出过期结果。** 所有状态变更都走串行渲染队列，并用递增的任务令牌守卫，
所以连续操作（拖动取景、反复输入体积）不会把旧结果画到界面上。

**切视图不重算。** 舞台里缓存了一份显示尺寸的成片副本，所以在两种预览视图之间来回
切换不会重新编码，只是重新定位裁剪框叠加层。

**刻意零依赖。** 全部逻辑在 `app.js`（经典 script + IIFE），全部样式在
`styles.css`（令牌集中在 `:root`，无魔法值），全部结构在 `index.html`。
没有框架、没有打包器、没有 CDN。

## 浏览器兼容

Chrome / Edge 90+、Firefox 90+、Safari 15+。需要 Canvas 2D、`toBlob`、
CSS Grid、`aspect-ratio`、指针事件与 File API。

几点说明：

- 解码能力取决于浏览器：JPG / PNG / WebP / GIF 到处都能用；BMP、AVIF 需要
  浏览器自身支持。
- 动图（GIF / 动态 WebP）只会载入其中一帧，导出永远是静态图。
- 超大素材（4000 万像素以上）会受浏览器画布上限约束且较慢；超过 800 万像素
  时会先给出提示。

## 开发与测试

没有东西需要构建。改这三个文件，刷新页面即可。

测试套件驱动真实浏览器、用程序注入图片，并校验**实际下载回来的字节**（含
JPEG / PNG magic bytes），而不是「假设成功」。

```bash
cd tests
npm install playwright-core     # 只需一次
node qa.mjs
```

使用你本机安装的 Chrome（`channel: 'chrome'`），不需要额外下载浏览器。43 条用例
覆盖：三种上传路径、10 个通用比例与 7 个平台预设的宽高比精度、自定义比例与非法
输入拦截、目标体积压缩（500 KB 与 80 KB 预算及达成率）、不可达目标的处理、放大
路径的正确性与提示的诚实度、JPG / PNG 导出、PNG 无损语义、预估准确性、非图片与
损坏文件的错误处理、取景微调、零外部请求、控制台干净。

产物（报告、截图、生成的样图、抓取到的下载文件）写入 `tests/output/`，已在
`.gitignore` 中。

### 独立验证

`tests/verify.mjs` 是第二套刻意对抗性的测试：它**重新解码下载到的文件、把像素读回来
核对**，而不是相信界面自己报的数字。覆盖内容包括：像素级的裁切内容与居中定位、预估
字节与真实下载字节逐字节一致、透明语义（PNG 保留 alpha、JPG 填指定背景色）、快速
改动设置时的竞态、边界与压力（1×1、4×4、8000×6000、100:1 与 1:100 比例、同一文件
连选两次）、WebP / GIF / BMP 源图，以及累计的 console 与网络清洁度。

```bash
cd tests
node verify.mjs
```

报告写入 `tests/output/VERIFY-REPORT.md`，并在 `tests/output-verify/VERIFY-REPORT.md`
留一份持久副本。它的样图与抓取到的下载文件放在 `tests/output-verify/` 这个独立根目录
下 —— `qa.mjs` 启动时会清空 `tests/output/`，两套测试因此可以用任意顺序运行而不会
互删产物。两个输出目录都已在 `.gitignore` 中。

## 路线图

- **批量处理** —— 一次处理多张。刻意推迟：它会让单图流程（也就是核心场景）的
  状态与界面复杂度翻倍。是计划内，不是被否掉。
- **WebP / AVIF 导出** —— 面向网页发布，那里页面重量比 JPEG 兼容性更重要。
- **前后对比** —— 可拖动的分割视图，对比原图裁切区与压缩后的成片，用眼睛判断画质损失。
- 更多平台预设，以及「一键导出某平台要的全部尺寸」的打包导出。
- 把编码管线搬进 Web Worker，让超大图不再阻塞界面。
